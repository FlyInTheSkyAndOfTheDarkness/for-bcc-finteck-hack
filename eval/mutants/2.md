## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Push-уведомление о зачислении заработной платы |
| **Продукт** | Мобильный банк |
| **Бизнес-процесс** | Информирование клиента о поступлениях на счёт |
| **Business owner / Product owner / Аналитик** | Руководитель направления зарплатных проектов / Владелец продукта «Мобильный банк» / Системный аналитик команды уведомлений |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, сервис зачислений, сервис уведомлений |
| **Задача в JIRA** | PAY-1024 |

### Цели
Клиент узнаёт о зачислении заработной платы не позднее чем через 2 минуты после зачисления средств на счёт. Бизнес-метрика: снизить число обращений в контакт-центр с вопросом о поступлении зарплаты на 20 % за первый квартал после запуска.

### Архитектура решения
Сервис зачислений → сервис уведомлений → push-провайдер. Мобильное приложение → сервис уведомлений (чтение и сохранение настройки).

### Дизайн процесса UI
Профиль → Уведомления → «Зачисление зарплаты». На экране есть переключатель «Уведомлять о зарплате» и подпись «Push придёт после зачисления средств на счёт». Состояние переключателя сохраняется сразу при нажатии. При ошибке сохранения переключатель возвращается в прежнее положение и показывается сообщение «Не удалось сохранить настройку, попробуйте позже».

### Требования к изменениям

#### BPMN схема процесса
Зачисление по зарплатному реестру → проверка настройки клиента → если уведомление включено, формирование push → отправка push → завершение. Если уведомление выключено — завершение без отправки.

#### Функциональные требования
* **ЗП-1.** Клиент с активным текущим счётом в KZT включает и выключает уведомление о зачислении заработной платы переключателем в приложении.
* **ЗП-2.** Для клиента, который ещё не менял настройку, уведомление о зачислении заработной платы включено.
* **ЗП-3.** Зачислением заработной платы считается зачисление на текущий счёт клиента с кодом назначения платежа (КНП) 311 по зарплатному реестру работодателя.
* **ЗП-4.** При зачислении заработной платы на счёт клиента с включённым уведомлением сервис уведомлений отправляет клиенту один push с текстом «Зачислена заработная плата: {сумма} ₸».
* **ЗП-5.** Сумма в тексте push равна сумме зачисления в тенге с двумя знаками после запятой и пробелом в качестве разделителя разрядов, например «250 000,00 ₸».
* **ЗП-6.** Если поступило несколько зачислений заработной платы, push отправляется по каждому зачислению.
* **ЗП-7.** Если уведомление выключено, push о зачислении заработной платы не отправляется, а история зачислений за последние 12 месяцев отображается в разделе «Уведомления».
* **ЗП-8.** Если push-провайдер не принял push, сервис уведомлений повторяет передачу до 3 раз с интервалом 30 секунд. После третьей неудачной попытки событие записывается в журнал ошибок.

### Sequence Diagram
Сервис зачислений → сервис уведомлений: событие `salary.credited`. Сервис уведомлений → хранилище настроек: получить настройку клиента. Сервис уведомлений → push-провайдер: текст push и идентификатор устройства клиента.

### Нефункциональные требования
* **НФ-1.** Сервис уведомлений передаёт push провайдеру не позднее 60 секунд после получения события для 95 % событий при нагрузке до 50 событий в секунду.
* **НФ-2.** Доступность сервиса уведомлений — не ниже 99,9 % за календарный месяц.
* **НФ-3.** Текст push не содержит номер счёта и наименование работодателя.

### Требования к данным
* Настройка: идентификатор клиента, признак включения уведомления (`salary_push_enabled`, boolean), дата и время изменения в UTC.
* Журнал отправок: идентификатор операции зачисления, сумма зачисления в тиынах (integer), время передачи провайдеру в UTC, результат передачи. Срок хранения журнала — 1 год.

### Требования к интеграции
* Сервис зачислений публикует событие `salary.credited` с полями `operationId` (string), `clientId` (string), `amountTiyn` (integer, сумма в тиынах), `knp` (string), `creditedAt` (ISO-8601, UTC).
* Повторная доставка события с тем же `operationId` не приводит к повторной отправке push.
* Приложение читает и сохраняет настройку методами части B.

## Часть B. REST API

Дочерний документ части A: «Уведомление о зачислении заработной платы — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Сохранение настройки уведомления о зачислении заработной платы |
| **REST type** | GET |
| **Authorization** | Bearer, сессия клиента |
| **Controller** | SalaryNotificationController |
| **Request URL** | Prod: `/v1/notifications/salary` |
| **CURL** | `curl -X GET "$BASE/v1/notifications/salary" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"enabled":true}'` |

Чтение настройки: `GET /v1/notifications/salary` без параметров; ответ совпадает с ответом метода сохранения при статусе 200.

### Логика работы метода
1. Проверить сессию клиента; при отсутствии или истечении сессии вернуть 401.
2. Определить клиента по сессии; идентификатор клиента в запросе не передаётся.
3. Проверить тело запроса; при ошибке вернуть 400.
4. Сохранить настройку и вернуть 200 с сохранённым значением.

### Параметры запроса

#### Request body
* **Content-Type:** `application/json`.

| Parameter | Format | Mandatory | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `enabled` | boolean | Да | Признак включения уведомления | `salary_push_enabled` |

### Ответ

| Parameter | Format | Description | DB field |
| :--- | :--- | :--- | :--- |
| `enabled` | boolean | Сохранённый признак включения | `salary_push_enabled` |
| `updatedAt` | string (ISO-8601, UTC) | Время изменения настройки | `updated_at` |

### Статусы

#### 200. Successful — Created
```json
{"enabled":true,"updatedAt":"2026-11-20T09:15:00Z"}
```

#### 400. Unsuccessful — Bad request
```json
{"code":"VALIDATION_ERROR","message":"Поле enabled обязательно"}
```

#### 401. Unsuccessful — Unauthorized
```json
{"code":"UNAUTHORIZED","message":"Требуется вход"}
```

#### 500. Unsuccessful — Internal server error
```json
{"code":"INTERNAL_ERROR","message":"Ошибка сервиса"}
```
