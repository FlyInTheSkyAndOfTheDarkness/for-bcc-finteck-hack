⚠️ R-02 — Клиент узнаёт о достижении личного бюджета в момент покупки

Вид: бизнес-цель · Место: Часть A. Новый функционал › Цели (стр. 1, стр. текста 20)

Дать клиенту возможность узнать о достижении личного бюджета в момент покупки.

D-032 🟡 незначительно Однозначность Термин «личный бюджет» не связан с порогом

Критерий: Однозначность (ISO/IEC/IEEE 29148:2018 §5.2.5; IEEE 830-1998 §4.3.2)

Цитата

о достижении личного бюджета

Место: Часть A. Новый функционал › Цели (стр. 1, стр. текста 20)

Почему это дефект: В R-02 используется «личный бюджет», а в функциональных требованиях — «порог» (R-06 Ф-1, R-08 Ф-3). Без явной связи цель можно понять шире: например, как отдельную сущность бюджета, не привязанную к карте.

Как исправить: Заменить на: «Дать держателю карты KZT возможность получить push, когда его расходы по карте за календарный месяц достигают заданного им порога».

уверенность 60% · источник: LLM: требование · подтверждено критиком

Замечания к набору, затрагивающие это требование: D-025, D-066

⚠️ R-03 — Архитектура: приложение → сервис настроек; процессинг → учёт расходов → сервис push

Вид: процесс · Место: Часть A. Новый функционал › Архитектура решения (стр. 1, стр. текста 24)

Мобильное приложение → сервис настроек. Карточный процессинг → учёт расходов → сервис push.

D-033 🟡 незначительно Полнота В архитектуре нет связи учёта расходов с сервисом настроек

Критерий: Полнота (ISO/IEC/IEEE 29148:2018 §5.2.5; IEEE 830-1998 §4.3.3)

Цитата

Карточный процессинг → учёт расходов → сервис push.

Место: Часть A. Новый функционал › Архитектура решения (стр. 1, стр. текста 24)

Почему это дефект: По R-03 учёт расходов не обращается к сервису настроек, хотя для проверки порога ему нужен порог карты. В R-10 есть шаг «Сервис расходов → настройки: получить порог карты». Схема архитектуры неполна, и по ней нельзя определить интеграции.

Как исправить: Дополнить: «Мобильное приложение → сервис настроек. Карточный процессинг → учёт расходов → сервис настроек (получение порога и признака включения) → сервис push»; названия компонентов привести к единым с R-10.

уверенность 70% · источник: LLM: требование · подтверждено критиком

Замечания к набору, затрагивающие это требование: D-026, D-067
