# План: агент проверки требований `reqcheck`

BCC-HUB x MNU FinTech Hackathon. Сдача: **27.11.2026, 23:59** (демо + репозиторий).
Критерии жюри, по 25%: **Уточнение · Архитектура · Ценность · Презентация**.

## 0. Решения
| Вопрос | Решение |
|---|---|
| LLM | Gemini, бесплатный тариф (Flash). Модель выбирается по списку `models.list` для ключа. Через адаптер подключаются OpenAI, Anthropic, Ollama |
| Вход | **PDF обязателен** (п. 3 ТЗ) + DOCX / MD / TXT / HTML |
| Интерфейс | CLI `python -m reqcheck <in> -o <out>` + Streamlit для демо |
| Уточнение | Раздел вопросов в отчёте + режим `--interactive` (вопросы в терминале или UI → повторная оценка) |
| Команда | Соло. Claude отвечает за код, eval, README, слайды, сценарий демо, GitHub |
| Исходники кейса | `task/` — клон репозитория организаторов, в git исключён. Входной документ копируется в `docs/` |

## 1. Архитектура (что показываем жюри)

```
                 ┌──────────── reqcheck (оркестратор, pipeline.py) ────────────┐
 файл ──► [1 Ingest] ──► [2 Segmenter] ──► [3 Linters]  ─┐                     │
 PDF/DOCX   блоки +        атомарные        правила,     │                     │
 MD/TXT     локаторы       требования +     без LLM      ▼                     │
                           grounding    [4 Req-Reviewer] ──► [6 Critic] ──► [7 Clarifier] ──► [8 Report]
                                        [5 Set-Reviewer] ─┘   проверка        вопросы          MD + HTML
                                         • противоречия       находок,        автору ТЗ        паспорт
                                         • прогон КП          дедуп,          (+ --interactive)
                                         • глоссарий/единицы  критичность
                                         • трассируемость
                                         • fintech-чек-лист
   инфраструктура: LLM-адаптер · кэш · rate-limit/retry · JSON-схемы · trace.jsonl · версия промптов
```

«Агентные» свойства, которые демонстрируем:
- роли с отдельными промптами;
- инструменты: поиск цитаты в документе, калькулятор сценариев для КП, словарь терминов;
- самопроверка через Critic;
- grounding: каждое замечание привязано к цитате, которая реально есть в тексте;
- human-in-the-loop через `--interactive`.

Fintech-слой (отдельный пакет проверок `checks/fintech.yaml`):
- деньги: единицы, минорные единицы (тиын), округление, валюта карты и операции;
- время: часовой пояс (Алматы — UTC+5 с 2024 г.), граница месяца, дата операции или дата проведения;
- жизненный цикл операции: авторизация, клиринг, возврат (частичный, после уведомления), отмена, chargeback;
- идемпотентность и порядок событий, повторная доставка;
- ИБ и ПДн: маскирование карты, данные в URL, GET для изменения состояния, IDOR (403 или 404), аудит;
- эксплуатация: откат, feature flag, SLA, нагрузка, мониторинг;
- процесс: версионность, согласования, трассируемость.

ML-слой:
- эталонная разметка и метрики recall, precision, F1;
- сопоставление находок с эталоном: место + критерий + LLM-judge;
- абляция по стадиям;
- оценка уверенности;
- проверка устойчивости на мутированных документах с внедрёнными дефектами.

## 2. Контракты (Ф0 — делает оркестратор до запуска агентов)
`reqcheck/models.py` (pydantic):
- `Block{id, part, section_path[], kind(text|table_row|list_item|code|heading), text, line_start, line_end, page?}`
- `Requirement{rid:"R-01", doc_id:"Ф-1"|None, kind(functional|nfr|data|integration|ui|acceptance|api|meta), text, quote, block_ids[], location:str}`
- `Finding{fid, scope(requirement|set), rids[], criterion(enum ISO/IEEE), severity(critical|major|minor), title, quote, location, explanation, recommendation, source(linter|llm_req|llm_set|scenario), confidence:0..1, verified:bool}`
- `Question{qid, fids[], question, why, options[], answer?}`
- `RunPassport{doc_name, doc_sha256, run_at, model, provider, agent_version(git), prompt_version, params}`
- `ReportData{passport, requirements[], findings[], questions[], set_summary, verdict{ready_dev, ready_test, top_fixes[]}}`

`reqcheck/llm.py` — интерфейс `LLMClient.generate_json(system, user, schema:type[BaseModel], *, tag) -> BaseModel` + `FakeLLM` (ответы из фикстур) для тестов.

Каждый агент работает только со своими файлами, импортирует контракты и не меняет их. Изменение контракта согласуется через оркестратора.

## 5. Риски
| Риск | Митигация |
|---|---|
| Лимиты бесплатного тарифа (429) | Пакетные запросы, кэш, rate limiter, запасная модель Flash-Lite |
| Галлюцинации, выдуманные цитаты | Grounding через fuzzy-match, Critic, отбраковка неподтверждённого |
| Подгонка под конкретный документ | Few-shot на чужих примерах, проверка на мутированных ТЗ |
| Конфликты при параллельной работе агентов | Жёсткое владение файлами, контракты в Ф0 |
| PDF ломает таблицы | Отдельный восстановитель таблиц, тест PDF = MD |
| Нехватка времени | Обязательный минимум к 14:00 — CLI + отчёт по п. 6. UI, мутации — по остатку |
